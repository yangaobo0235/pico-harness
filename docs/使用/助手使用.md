# 助手使用

以下使用独立命令 `pico`。在源码仓库运行开发版本时加 `uv run` 前缀。先完成[安装与配置](安装与配置.md)，再选择入口。

## 选择入口

| 入口 | 命令 | 使用场景 |
| --- | --- | --- |
| 终端界面 | `pico` | 持续对话、工具事件、交互与会话管理 |
| 单次任务 | `pico run -m "分析项目入口"` | 一项任务或脚本调用 |
| 交互 CLI | `pico run` | 在同一进程持续输入 |
| 消息 Gateway | `pico gateway --workspace /path/to/workspace` | 接收启用渠道的消息和定时任务 |
| 执行记录 | `pico tracing` | 在浏览器分析模型、工具和调用用量 |

TUI 需要实际终端或 IDE 模拟终端。Python 宿主负责执行，界面负责输入和展示。默认操作当前项目；指定目录使用 `pico run --workspace /path/to/project -m "..."`。限制与存储位置见[配置与状态](../参考/配置与状态.md)。

## 对话与会话

一次请求称为 Turn，一段持续对话称为 Session。一次请求可以包含多次模型调用和工具执行；同一会话的请求按序处理。

```powershell
pico sessions list
pico run --continue -m "继续说明上一步的调用链"
pico run --resume <session-id>
pico sessions --help
```

`<session-id>` 用列出的会话 ID 替换，按帮助选择查看或导出操作。`--session`、`--continue`、`--resume` 互斥。普通独立 CLI 调用默认新建会话。

恢复会话读取历史，不会重新执行过去的文件修改、Shell 命令或消息投递，也不会撤销副作用。取消与退出由对应入口处理；退出前确认需要保留的任务和会话状态。

脚本调用可用 `pico run --no-markdown -m "..."`，同时检查退出码和实际结果。模型声称成功不代替工具返回和文件/渠道事实。

## 消息渠道

支持飞书、企业微信、QQ，先安装对应 extra，并配置应用凭证、平台权限、发送者及群消息规则，再启用渠道。

```powershell
pico channels list
pico channels show feishu
pico gateway --workspace /path/to/workspace
```

飞书使用 WebSocket 长连接，需启用机器人、接收事件并发布应用；其他渠道按其平台要求准备。测试时用专用会话发送消息，分别确认入站、模型/工具执行、最终回复和回复地址。Gateway 存活或配置保存成功不能证明收发链路通过。运行与停止见[运行与发布](../运维/运行与发布.md)。

## 定时任务

```powershell
pico cron list
pico cron --help
```

按子命令帮助维护时间、任务内容与投递目标。到期任务复用 Agent 执行机制。CLI/TUI 来源的任务由对应交互进程处理，该进程必须保持运行；Gateway 只拥有启用消息渠道的任务。关闭交互终端后，不能期待 Gateway 自动接管其提醒。

## 技能与插件

工作区技能使用 `<workspace>/skills/<name>/SKILL.md`，内置技能位于 `src/pico/resources/skills`。用 `pico skills --help` 查看管理入口。技能被发现、本轮注入和实际执行效果分别核实，关闭外部长期记忆不影响本地技能。

`pico plugins --verbose` 查看插件来源、声明及 Backend 选择。插件与 MCP 是执行能力，接入方式见[扩展开发](../开发/扩展开发.md)，不能只凭名称或安装成功认定其可信或可用。

## 查看执行过程

运行 `pico tracing` 打开查看器，选择记录后检查模型输入/输出、工具、用量及相关产物。可按时间、状态、模型筛选，在 API 用量看板跳转记录，用全文搜索定位产物文本。查看器支持中英文、详情展开和自动刷新；停止后页面会显示服务已停止。

Trace 的缺失、截断或工具失败需结合日志排查。`pico doctor --json` 检查静态配置，`pico doctor --probe` 验证真实模型连接；连接与交付问题见[故障排查](../运维/故障排查.md)。
