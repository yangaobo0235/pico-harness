# 安装与配置

本页帮助你从空环境启动 Pico。日常操作见[助手使用](助手使用.md)，开发调试见[本地开发](../开发/本地开发.md)。Pico 的运行时是 Python，终端界面和执行记录查看器使用 Node.js。

## 准备条件

| 条件 | 用途 |
| --- | --- |
| Python 3.12 | Agent、CLI、RPC 和 Gateway |
| Node.js 22 与 npm | 构建及运行 React + TS 的 TUI、Trace 查看器 |
| uv、Git | 获取源码、安装 Python 依赖 |
| 模型端点、模型名、凭证 | 执行真实任务；配置和静态检查不等于模型已连通 |

基础 CLI/TUI 无需数据库或消息队列。消息渠道需要对应平台应用；Sandbox 需要额外依赖及虚拟化支持。Windows 可开发和运行核心功能，Boxlite 与 POSIX 专属接口要在支持的平台验证。

## 从源码安装

```powershell
git clone https://github.com/yangaobo0235/pico-harness.git
Set-Location pico-harness
uv sync --frozen --extra dev
npm ci
npm run build
uv run pico --version
```

预期最后一条显示版本。`npm ci` 在仓库根目录执行，`npm run build` 同时生成 TUI 和 Trace 资源。需要全部消息渠道时，第一条依赖同步命令改为 `uv sync --frozen --extra dev --extra channels`。

## 配置并执行第一项任务

```powershell
uv run pico onboard --skip-memory
```

按向导选择 Provider、模型、端点、凭证和执行环境。公开发行包不附带外部长期记忆实现，`--skip-memory` 关闭该 Backend，仍保留会话、历史、上下文与本地技能。向导默认发送首次真实请求；若暂不请求模型，追加 `--skip-test`，之后运行 `uv run pico doctor --probe`。真实请求可能产生费用。

```powershell
uv run pico doctor --json
uv run pico
```

`doctor --json` 验证静态配置，`pico` 在实际终端打开 TUI。执行单次任务可用 `uv run pico run -m "阅读 README，说明项目用途"`。任务使用的工作目录、文件限制和状态目录见[配置与状态](../参考/配置与状态.md)。

## 安装可在其他项目运行的命令

在已经构建资源的源码根目录执行：

```powershell
uv tool install .
```

需要飞书、企业微信和 QQ 时使用 `uv tool install ".[channels]"`。随后进入目标项目直接运行 `pico`。`uv run pico` 使用开发环境；独立安装的 `pico` 使用安装包，修改源码后需按[运行与发布](../运维/运行与发布.md)重新构建并安装。

若暂不独立安装，在目标项目使用 `uv run --project /absolute/path/to/pico-harness pico`，替换为源码实际路径。

## 使用安装脚本

Linux/macOS：`sh scripts/install/install.sh`。

Windows：`powershell -ExecutionPolicy Bypass -File scripts/install/install.ps1`。

脚本的制品和依赖来源可通过 `PICO_REPO_URL`、`PICO_WHEEL_URL`、`PICO_PYPI_INDEX`、`PICO_NPM_REGISTRY` 选择。使用明确来源并核对版本；安装失败按[故障排查](../运维/故障排查.md)区分 Python、Node、资源和配置问题。
