# 配置与状态

本页维护配置来源、关键配置块和持久化职责。首次创建配置使用[安装向导](../使用/安装与配置.md)，不要把包含凭证的真实配置作为示例提交。

## 配置来源

| 内容 | 规则 |
| --- | --- |
| 产品根目录 | 默认 `~/.pico`，可通过 `PICO_HOME` 覆盖 |
| 主配置 | 默认产品目录下的 `config.json` |
| 独立实例 | 支持该参数的入口用 `--config /path/to/config.json`；实例数据基于该文件的父目录 |
| 命令参数 | 例如 `--workspace`、Gateway `--port` 覆盖相应运行选项；以入口帮助为准 |
| 字段写法 | 支持配置模型约定的 camelCase 与 snake_case 名称 |

完整字段、类型和默认值以[基础配置模型](../../src/pico/config/models/runtime.py)、[功能配置模型](../../src/pico/config/models/features.py)为准；加载逻辑见[配置加载](../../src/pico/config/loader.py)。新增字段同步模型、消费者和适用示例，不在文档维护第二份完整 Schema。

首次向导填写的 API Key 保存在相应 Provider 的配置中。Windows 的 `~` 通常是 `C:\Users\<用户名>`；不确定当前配置位置时运行 `pico doctor --json`，查看 `paths.config_path`，无需打印密钥。`PICO_HOME` 或 `--config` 会改变位置。

## 最小模型配置

下面是连接 OpenAI 兼容端点、关闭外部记忆的配置片段。请替换占位模型、端点和 Key，并在对应配置文件执行诊断。

```json
{
  "agents": {"defaults": {"provider": "custom", "model": "your-model"}},
  "providers": {"custom": {"apiBase": "https://your-endpoint.example/v1", "apiKey": "replace-with-your-key"}},
  "tools": {"restrictToWorkspace": true},
  "memory": {"backend": null}
}
```

文件边界限制不等于开启 Sandbox。Shell 的执行环境由 `tools.sandbox` 决定。静态诊断 `pico doctor --json` 与真实探测 `pico doctor --probe` 分别验证配置和请求，诊断入口与实际运行必须选择同一配置。

## 配置块归属

| 配置块 | 主要责任 |
| --- | --- |
| `agents.defaults`、`providers` | 默认模型、上下文/迭代限制、工作区、端点和凭证 |
| `tools` | 文件边界、Shell、Sandbox、MCP、工具启停 |
| `channels` | 飞书/企业微信/QQ、接收者规则与进度消息 |
| `gateway` | 健康端口、并发池、发送重试及日志轮换 |
| `context`、`runtime` | 上下文预算、历史策略、执行限制和检查点 |
| `memory`、`plugins` | 外部 Backend、插件启停与专属配置 |
| `routing` | 可选模型路由策略 |
| `tracing`、`callEfficiency` | 执行记录、调用缓存、用量计量 |

`pico channels show <name>` 查询渠道字段；`pico provider --help` 查询 Provider 管理。渠道名称为 `feishu`、`wecom`、`qq`。保存凭证后还需验证平台权限和真实收发。

## 工作目录和状态根目录

| 启动方式 | 工具工作目录 | 会话等项目状态 |
| --- | --- | --- |
| 默认前台 CLI/TUI | 当前项目 | `<产品根>/projects/<目录名>-<路径摘要>` |
| 显式 `--workspace` | 指定目录 | 同一指定目录 |
| 配置自定义 workspace | 配置目录 | 同一配置目录 |
| Gateway | 配置或参数指定目录 | 同一目录 |

默认项目状态根据解析后的绝对路径隔离；搬迁项目可能改变项目 ID。实例级 Cron、日志、Sandbox 等目录由活动配置的父目录派生。路径的唯一实现见[路径规则](../../src/pico/config/paths.py)与[项目身份](../../src/pico/config/identity.py)。

## 持久化职责

Pico 当前使用文件持久化，不需要关系数据库。下表说明应备份什么，以及谁负责读取；字段明细随所属模型演进，不另建无消费者的数据字典。

| 数据 | 位置/形态 | 责任和生命周期 |
| --- | --- | --- |
| 会话 | `<状态根>/sessions/<渠道>/<会话>.jsonl` | 元数据与消息事实；会话服务负责锁、追加、原子改写和代际边界 |
| Cron | `<配置父目录>/cron/jobs.json` 及锁 | 持久任务定义；由相应宿主执行，不等于已投递 |
| Gateway | `<配置父目录>/logs/gateway.log`、`gateway.lock` 及锁锚点 | 日志诊断和实例互斥；锁由操作系统释放，不能靠删除载荷终止进程 |
| Trace | 对应记录状态根的 `logs/`、`logs/audit-artifacts/`、归档 | 事件、调用及详情产物；查看器投影这些记录，不把显示结果作为执行事实 |
| Sandbox | `<配置父目录>/sandbox/<backend>/` | 后端运行资源，是否可删除由后端和备份策略决定 |
| 缓存 | `<配置父目录>/cache/` 等所属缓存 | 可重建数据，不能成为唯一业务事实 |
| 技能、模板、外部记忆 | 对应工作区/插件目录 | 技能为程序输入；外部 Backend 的存储与兼容由插件负责 |

会话模型与格式见[会话模型](../../src/pico/runtime/sessions/models.py)、[会话服务](../../src/pico/runtime/sessions/service.py)，Trace 写入见[记录存储](../../src/pico/observability/tracing/store.py)。恢复会话不恢复进程内执行器或重放工具副作用。

## 插件与执行环境配置

`plugins.disabled` 按插件 ID 禁用，`plugins.config` 提供专属配置；`memory.backend = null` 关闭外部长期记忆。公开包不附带外部长期记忆实现，启用前安装兼容插件。

Sandbox extra 为 `sandbox`，当前依赖 Boxlite 0.9.5。Windows 无对应发行 wheel；在支持平台安装后，还需验证实际 VM、镜像、权限及资源条件。SDK 导入成功不等于可以启动沙箱。接入协议见[扩展开发](../开发/扩展开发.md)。备份、更新和恢复见[运行与发布](../运维/运行与发布.md)。
