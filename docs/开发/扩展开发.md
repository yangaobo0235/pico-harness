# 扩展开发

本页说明新增能力该放在哪里，以及怎样同步契约、资源和验证。先按[开发规范](开发规范.md)判断职责，再用[项目结构](项目结构.md)定位调用链；这里不重复完整接口字段。

## 选择接入方式

| 需求 | 接入位置 | 验证重点 |
| --- | --- | --- |
| 工作流程与提示说明 | 工作区或内置 `SKILL.md` | 发现、选择、上下文注入与实际效果 |
| 新工具 | `capabilities/tools` 或插件工具贡献 | 参数、结果、权限、失败、取消及资源关闭 |
| 外部工具服务 | MCP 配置与 `integrations/mcp` | 协议、超时、取消、连接关闭和权限 |
| 模型服务 | `integrations/llm` 与装配/配置 | 请求、流式响应、工具调用及用量映射 |
| 消息渠道 | `integrations/channels` 与渠道管理 | 入站身份、会话地址、回复、重连和关闭 |
| 长期记忆 | Memory Backend 插件 | 协议、持久化、召回、兼容与生命周期 |
| Shell/VM 后端 | `integrations/execution` | 工作区映射、权限、超时、取消和真实执行 |
| 新入口或展示 | `interfaces` 或前端所属 feature | 复用现有用例/运行时，协议和消费者一致 |

技能说明不是新增宿主代码能力的替代。新的外部接口或执行机制由代码接入；不把任意执行逻辑塞进配置，也不复制运行时调度。

## 插件声明与工厂

插件使用 `pico-plugin.toml` 声明身份、版本、Pico 兼容范围和贡献。目前支持 `memory_backends` 与 `tools`。最小结构示意：

```toml
[plugin]
id = "example-tool"
version = "0.1.0"
enabled_by_default = true

[[plugin.contributes.tools]]
name = "example_tool"
factory = "example_package.tool:create_tool"
```

工厂接收 `PluginContext`，返回对应协议对象。`config` 是插件自己的配置片段，工厂必须验证实际消费字段；Manifest 的 `config_schema` 当前只是描述信息。`services` 只暴露宿主显式提供的能力，当前为 workspace，`logger` 带插件身份。

参考[Manifest 模型](../../src/pico/integrations/plugins/manifest.py)、[插件上下文](../../src/pico/integrations/plugins/context.py)、[工具协议](../../src/pico/capabilities/tools/contracts.py)和[记忆协议](../../src/pico/capabilities/memory/contracts.py)。Manifest 合法只证明声明可解析，不证明工厂可以导入或返回正确对象。

## 发现、启用与生命周期

宿主使用内置位置、产品目录的用户插件和已安装的 `pico.plugins` entry point；工作区 `.pico/plugins` 不自动作为执行来源。底层发现器支持更多来源，不表示产品宿主全部开放。实际来源以 `pico plugins --verbose` 和[宿主发现配置](../../src/pico/bootstrap/plugins.py)为准。

按 ID 去重、身份/版本校验、启停规则、贡献注册和工厂激活分别确认。用户路径安装或发行包 entry point 的具体声明必须匹配发现器和实际文件清单；先运行发现诊断，再做工厂与协议集成测试。

插件在宿主进程执行 Python，冻结的上下文对象不是进程级 Sandbox。资源的启动、关闭、失败清理和取消传播要与宿主生命周期对接；不能让后台任务在所属运行时关闭后继续存活。

## 修改 RPC 或 Trace API

1. 在 `contracts/rpc/openrpc.json` 或 `contracts/tracing/api.schema.json` 修改消息语义，明确可选字段、错误和兼容旧记录的行为。
2. 运行 `npm run gen:contracts`，同步 Python 生产方、TS 消费者及生成文件，避免手改生成输出。
3. 运行 `npm run check:contracts`、TUI `lint:rpc` 与 `lint:rpc-surface`，并做相关契约/消费者回归。
4. 修改跨框架原始 Trace 解析时，保留开放扩展字段与历史可空状态；新增规范化校验不能无意缩窄历史读取范围。

共享类型不代替运行时校验。协议和插件变更涉及安装资源时，增加[独立发行校验](../运维/运行与发布.md)。

## 文档与验收

能力配置写[配置与状态](../参考/配置与状态.md)，操作写[助手使用](../使用/助手使用.md)，新边界写项目结构，平台限制写测试或运维主题。内置技能的 `SKILL.md` 与运行时模板属于产品输入，随能力维护，不作为重复手册。

测试先验证协议和受控依赖，再在适用平台验证实际连接。真实模型、渠道和 VM 的准入条件及命令见[测试说明](测试说明.md)；未具备条件时保留未验收项。
