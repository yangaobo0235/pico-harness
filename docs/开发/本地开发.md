# 本地开发

使用依赖为 Python 3.12、Node.js 22、npm、uv 与 Git。所有命令默认从仓库根目录执行。面向使用者的安装与首次配置见[安装指南](../使用/安装与配置.md)。

## 准备开发环境

```powershell
uv sync --frozen --extra dev --extra channels
npm ci
npm run build
uv run pre-commit install
uv run pre-commit install --hook-type commit-msg
```

只开发 CLI/TUI 可省略 `--extra channels`。根 npm workspaces 管理全部 JS 应用和契约包，只维护根锁文件，在根目录执行 `npm ci`；不要在各应用另建锁文件。Sandbox 按支持平台安装，见[配置与状态](../参考/配置与状态.md)。

## 启动和调试

| 目标 | 命令 | 说明 |
| --- | --- | --- |
| CLI | `uv run pico run -m "..."` | 使用当前 Python 源码，真实任务需要模型配置 |
| TUI | `uv run pico` | 启动构建后的 Ink 界面与 Python RPC 宿主 |
| TUI 构建 | `npm run build:tui` | 修改界面后重新生成 bundle |
| Gateway | `uv run pico gateway --workspace /path/to/workspace --verbose` | 使用专用测试配置与目录，避免接入日常渠道 |
| Trace 服务 | `node apps/tracing-viewer/server.js` | 先构建；默认本地端口 4318 |
| Trace 页面热更新 | `npm --prefix apps/tracing-viewer run dev` | Vite 页面代理请求到 4318，另开终端运行服务 |
| 两应用构建 | `npm run build` | 生成 TUI 和 Trace 的发行资源 |

Trace 的配置参数以 [package.json](../../apps/tracing-viewer/package.json)和[服务配置](../../apps/tracing-viewer/src/server/config/viewer.ts)为准。需要隔离数据时使用服务支持的 `--state-dir`，不要读取私人 Trace 作为测试夹具。

IDE 使用仓库 `.venv` 解释器，运行模块 `pico`，将 `src` 标记为 Sources Root。TUI 控制台开启模拟终端；工作目录选择希望助手处理的项目。Windows 控制台出现编码问题时设置 `PYTHONUTF8=1`、`PYTHONIOENCODING=utf-8`。使用包安装或 `uv run` 加载 `src/pico`，避免依靠把源码复制到仓库根目录运行。

## 契约和检查

```powershell
npm run gen:contracts
npm run check:contracts
uv run python -m scripts.ci.check_architecture
npm run check:architecture
uv run python -m scripts.ci.check_docs
```

RPC/Trace Schema 改动同步生成 TS 类型与校验器。完整 lint、类型、回归和构建顺序见[测试说明](测试说明.md)，代码归属见[架构](项目结构.md)。发行资源定位或安装流程变化按[运行与发布](../运维/运行与发布.md)验证。
