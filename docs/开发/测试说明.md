# 测试说明

Pico 将确定性回归、实际平台安装和真实外部链路分开验证。每次交付说明具体环境、命令、结果、跳过及未覆盖范围。开发依赖见[本地开发](本地开发.md)。

## 测试位置

| 目录 | 责任 |
| --- | --- |
| `tests/unit` | 职责模块与受控依赖 |
| `tests/contracts` | Provider、Backend、插件和协议约定 |
| `tests/integration` | 跨模块、持久化与生命周期 |
| `tests/e2e` | 实际子进程、终端及测试驱动器 |
| `tests/packaging`、`tests/tooling` | 安装资源、发行门禁、仓库策略与脚本 |
| `tests/fixtures` | 脱敏、可提交的测试输入 |
| `apps/tui/tests/unit` | 组件、Hook、状态、终端与 RPC 客户端 |
| `apps/tracing-viewer/tests` | React、请求生命周期、响应契约和真实 Node 服务 |

## 标准本地检查

在仓库根目录执行。支持 Make 时可运行 `make check`；以下命令也适用于 Windows。

```powershell
uv run ruff check src scripts tests benchmarks hatch_build.py
uv run ruff format --check src scripts tests benchmarks hatch_build.py
uv run python -m scripts.ci.check_architecture
uv run python -m scripts.ci.check_repository
uv run python -m scripts.ci.check_docs
npm run lint
npm run check:architecture
npm run check:contracts
npm --prefix apps/tui run lint:rpc
npm --prefix apps/tui run lint:rpc-surface
npm run typecheck
npm run build
uv run pytest tests -n 4 -q --strict-markers
npm test
```

Trace 的 Node 集成测试依赖构建产物；单独运行时先 `npm run build:tracing`，再 `npm run test:tracing`。根 `npm test` 运行两应用和 TS 架构脚本测试。

## 按改动选择验证

| 改动 | 检查与依据 |
| --- | --- |
| 局部行为 | 对应单元测试，验证实际触发输入、结果及失败条件 |
| 取消、关闭、恢复 | 相关集成测试，验证资源和状态；信号处理增加真实子进程检查 |
| RPC/Trace 契约 | Schema 生成一致性、服务契约和消费者回归 |
| TUI 交互 | 组件与状态回归，再验证真实 PTY 的输入、取消和退出 |
| 安装/资源定位 | 仓库外 wheel、sdist、独立环境和安装后运行 |
| 文档导航和目录 | 文档链接与仓库策略检查 |

例如 Agent 执行逻辑可先运行 `uv run pytest tests/unit/runtime/agent -q`。Gateway 停止检查运行 `uv run pytest tests/unit/interfaces/cli/test_cli_gateway_signals.py tests/unit/interfaces/cli/test_cli_gateway_commands.py -q`。不要只因退出码属于宽泛范围就认为清理完成，检查清理行为与强制终止标记。

## 显式选择的真实测试

默认测试排除以下标记，不能把默认回归通过解释为这些链路通过：

| 标记 | 必要条件 |
| --- | --- |
| `real_llm`、`llm_judge` | 明确的模型、可用凭证和请求预算 |
| `real_channel` | 专用平台应用、凭证、消息测试目标及收发权限 |
| `real_vm` | 支持的虚拟化环境、镜像和运行资源 |
| `external_runtime` | 指定外部程序与兼容版本 |
| `e2e` | 测试文件要求的子进程、PTY 驱动器或终端 |
| `performance` | 独立计时环境，避免与并行回归争用 |

选择具体文件，例如 `uv run pytest <test-file> -m real_llm -n 0 -q`。先读文件确认是否使用项目认可的测试配置；不要扫描用户密钥并自动向私人渠道发消息。性能单独执行 `uv run pytest tests -m performance -n 0 -q`，记录环境和原始结果，失败时不临时放宽阈值。

毫秒级异步性能实验同时核对请求延迟和实际唤醒延迟。操作系统的定时器粒度可能大于实验设置，此时收益比不能直接跨平台比较。Git 快照分别记录首次全量和后续增量开销，区分暂存、提交与文件系统成本。保留原配置下的失败，不能用另一平台通过覆盖本平台未达标的结果。

## 跨平台与 PTY

Windows 检查核心 CLI、运行时、前端和 SIGBREAK 停止；Linux 检查 POSIX 信号、PTY、文件描述符、Unix Socket 与权限位。符号链接按实际权限探测。Linux 容器能验证用户态运行与安装，但不能替代宿主真实终端或 VM 能力。

现有 `tests/e2e/tui/autotest` 通过外部 `tui-use` 驱动 PTY。运行前确认该程序存在，阅读所选测试，避免混入真实模型测试。可先运行不依赖模型的终端驱动 smoke，再在专用配置下验证 Pico 的空闲退出、输入取消、会话与流式交互；不能将 `pico --check` 当作完整 PTY 验收。

无模型交互测试使用明确 Provider、模型和假凭证，并将端点指向隔离的本机测试服务或不可用端口，关闭渠道和不需要的能力。先等待 RPC/会话进入 ready，再输入命令；初始 Logo 或输入框出现不表示初始化完成。驱动器需要持续读取终端输出并等待操作结果，避免缓冲阻塞或过早输入造成误判。空闲退出、输入取消和本地命令可以独立验证，真实模型流式交互另行验收。

## 发行和证据

完整发行门禁必须检查 `base,channel-feishu,channel-qq,channel-wecom,channels,sandbox` 六套独立安装。当前 Windows 无 Boxlite 发行 wheel；五套安装通过不能标记六套门禁通过。在支持的 Linux/macOS 环境完成 Sandbox 安装后，真实 VM 仍要另行验收。

构建、隔离环境和报告说明见[运行与发布](../运维/运行与发布.md)。本机日志与 JSON 保存在 Git 忽略的 `.pico/` 或仓库外目录，正式手册维护命令和判定方式，不持续追加每次执行计数。能力与成本评测见[Benchmark 说明](../../benchmarks/README.md)。
