# 故障排查

先确定失败发生在启动、配置、模型、工具还是交付，再收集版本、命令、退出码和脱敏日志。独立安装使用 `pico`，源码环境使用 `uv run pico`。

## 从哪一步检查

| 顺序 | 命令/动作 | 能说明什么 |
| --- | --- | --- |
| 1 | `pico --version` | Python 入口可启动 |
| 2 | `pico --check` | TUI 资源与基础启动条件；不等于完整交互通过 |
| 3 | `pico doctor --json` | 静态配置是否有效 |
| 4 | `pico doctor --probe` | 真实模型连接与请求，可能产生费用 |
| 5 | `pico tracing`、Gateway 日志 | 实际执行阶段、工具、错误和交付事实 |

诊断与实际运行选择相同的配置、工作目录与安装环境。

## 启动与安装

| 现象 | 处理 |
| --- | --- |
| 找不到 pico | 检查独立工具安装和 PATH；源码先用 `uv run pico` |
| Python 找不到模块 | 确认 `uv sync` 与 IDE `.venv` 解释器；开发采用 `src/pico` 布局 |
| TUI 或 Trace 资源缺失 | 根目录 `npm ci`、`npm run build`，独立安装重新构建并安装 |
| Node 找不到或版本错误 | 检查 Node.js 22 与启动进程实际 PATH，重新加载 IDE/终端 |
| TUI 没有 TTY | 在实际终端或 IDE 模拟终端启动，检查重定向 |
| 渠道缺少 SDK | 在运行命令所用环境安装对应 `channel-*` 或 `channels` extra |
| Windows 无法安装 sandbox | Boxlite 0.9.5 无 Windows wheel，使用受支持平台；不能用跳过安装证明 VM 可用 |

安装和源码更新方法见[安装与配置](../使用/安装与配置.md)与[运行与发布](运行与发布.md)。

## 配置和模型

先检查 Provider、模型名、端点、凭证及配置路径，再查网络和模型请求返回。配置可解析、模型名合法不等于服务可达。`doctor --probe` 会发送真实请求。

公开包缺少外部 Memory Backend 时使用 `pico onboard --skip-memory`；重新设置已有配置可用向导 `--reset`，操作前备份。关闭外部 Backend 不会关闭会话和本地技能。路径与字段见[配置与状态](../参考/配置与状态.md)。

## Gateway、渠道与定时任务

| 现象 | 定位步骤 |
| --- | --- |
| 提示已有实例 | 检查同一配置父目录的持锁进程，正常停止；不要只删除锁文件 |
| 健康端口不可用 | 查绑定告警、端口冲突和实际实例；健康失败时 Gateway 仍可能运行 |
| 启动超过探针 30 秒 | 保留 stdout/stderr、启动日志与当时负载，查导入/资源启动；重试结果与首次失败分别记录 |
| Windows 停止返回 3221225786 | 即 0xC000013A；确认运行的是含 SIGBREAK 处理的新安装包，正常进程组停止应走清理；强制结束不算成功 |
| 消息未进入 | SDK、凭证、应用发布、事件权限、发送者/群规则和连接状态 |
| 已执行但没有回复 | 核对原会话/话题地址、交付重试、渠道传输错误及平台发送结果 |
| Cron 不投递 | `pico cron list` 核对任务、时间与目标，确认拥有该来源任务的进程仍在运行 |

健康接口只证明监听存活。真实渠道按“入站 → 请求执行 → 交付 → 收件会话”核对；不能只看模型生成了文本。CLI/TUI 的提醒不由 Gateway 自动接管。

## 工具、会话和记录

文件失败先查工作目录、边界和权限；Shell/Sandbox 失败查后端、平台、超时与真实运行资源。插件问题先用 `pico plugins --verbose` 核对来源和声明，再检查激活、配置和协议。

会话不见时，核对当前目录、`--workspace`、`--config` 与 `PICO_HOME`，然后 `pico sessions list`。项目路径搬迁可能改变默认状态标识。不要通过清空状态解决读取问题；发现损坏先备份并保留错误。

Trace 无记录时核对记录开关、状态目录和启动输出；页面看到的近期数据不代表所有历史都已加载。工具副作用需要以实际文件或外部结果确认，恢复对话不会撤销过去操作。

## 报告问题

提供系统、Python/Node/Pico 版本、启动入口、复现步骤、预期和实际结果，以及退出码和脱敏日志。说明验证使用受控依赖还是真实模型/渠道/VM。不要提交凭证、私人会话和真实原始产物；安全问题按 [SECURITY.md](../../SECURITY.md)私下提交。
