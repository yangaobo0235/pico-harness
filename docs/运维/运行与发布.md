# 运行与发布

本页维护长期运行、备份、更新回退和发行门禁。第一次安装见[安装与配置](../使用/安装与配置.md)，字段与路径见[配置与状态](../参考/配置与状态.md)，具体故障见[故障排查](故障排查.md)。

## 启动 Gateway

使用专用工作目录和明确的配置，安装启用渠道的依赖：

```powershell
pico gateway --config /path/to/config.json --workspace /path/to/workspace --port 18790
```

预期日志显示启用渠道和健康监听。健康接口当前绑定 `127.0.0.1`，返回 `{"status":"ok"}`；它只证明进程监听存活，不证明模型、平台认证、收发或工具执行正常。绑定失败时 Gateway 会告警并继续运行，运维必须核实健康端点属于目标实例。

同一实例由配置父目录下的锁保护，重复启动会失败。不同配置若放在同一父目录，实例数据和锁仍共享；隔离实例需独立配置目录、工作区及端口。Cron 和消息渠道的真实交付按[助手使用](../使用/助手使用.md)验证。

## 正常停止

- 前台 Ctrl+C 触发 asyncio 取消和资源清理。
- POSIX 服务停止使用 SIGTERM；Windows 新进程组可发送 CTRL_BREAK_EVENT，对应 SIGBREAK。
- 停止请求进入 Gateway 清理链，重复 SIGTERM/SIGBREAK 不打断清理；再次 Ctrl+C 仍遵循 asyncio 的强制中断行为。等待进程退出后再替换安装包或重启。
- Windows `TerminateProcess`、任务管理器强制结束、POSIX SIGKILL 不保证异步清理，不作为正常停止验收。

宿主依次关闭健康监听、Cron、待答问题、渠道入站、调度和交付、渠道传输、Agent 与运行资源。清理尽量尝试全部步骤，错误保留在日志中。停止超时要保留日志并定位，不能把强制终止或 `0xC000013A` 异常退出视作通过。

## 日志与 Trace

Gateway 日志位于活动配置父目录的 `logs/gateway.log`，配置 `gateway.log` 控制级别、轮换和保留，默认按 10 MB 轮换、保留 7 份。`--verbose` 用于开发排查。Trace 与详情产物使用自身记录状态根，由 `pico tracing` 打开查看器；启动输出和配置确认实际路径。

查看器本地服务默认端口 4318，不作为公网 Agent API 部署。停止操作走受保护接口；历史记录和产物仍可能包含提示词、工具参数与响应，备份或共享前按内容脱敏。

## 备份、更新与回退

1. 记录当前 Pico、Python、Node 版本和安装来源，停止相关宿主并等待退出。
2. 备份实际配置、项目状态、Cron、所需技能和插件，以及需要保留的 Trace/产物；路径按配置与状态核实，不能只备份源码目录。
3. 更新源码和锁文件，在根目录执行 `npm ci`、`npm run build`。重新安装独立工具可用 `uv tool install --reinstall .`，渠道安装使用 `uv tool install --reinstall ".[channels]"`。
4. 核对版本，运行静态诊断、TUI 检查和健康检查；根据使用范围验证模型、渠道、定时任务和执行环境。
5. 失败时保留错误与日志，回到上一版本源码/安装包及匹配锁文件、前端资源。若变化包含状态格式迁移，按该变化的迁移与备份恢复方案操作。

本次结构改造没有引入数据格式升级。回退不清空 `.pico`、Home 配置、会话或 Trace；不能通过删除锁文件代替停止持锁进程。恢复会话不撤销或重放工具副作用。

## 构建发行包

从仓库根目录执行：

```powershell
npm ci
npm run build
uv build
```

wheel 包含 Python、内置资源、TUI 和 Trace 生产产物，不携带 node_modules 或 TS 开发工具。sdist 携带重建所需源码、Schema、配置和预构建资源。新增依赖或 bundle 内容同步 [NOTICES.md](../../NOTICES.md) 与 `LICENSES/`，资源清单以[构建钩子](../../hatch_build.py)和发行校验器为准。

## 完整独立发行门禁

在仓库根目录运行下列命令，`--output-root` 必须为仓库外尚不存在或为空的专用目录。替换占位路径，避免与已有测试证据混用：

```powershell
uv run python -m scripts.release.verify_distribution --output-root /absolute/path/outside-checkout/pico-distribution --entrypoint pico --extras base,channel-feishu,channel-qq,channel-wecom,channels,sandbox
```

支持 Make 时设置 `PICO_RELEASE_OUTPUT` 后运行 `make release-dist`。校验器复制源码快照、构建 wheel/sdist、检查清单，建立六套独立环境，检查可选导入隔离、包路径、命令、配置缺失诊断、插件与基础运行面，再从 sdist 重建 wheel 比较内容，并确认验证期间源状态不变。

base 运行面包含 TUI `--check` 和真实 Gateway 进程的健康、稳定、正常停止。Gateway 默认就绪 30 秒、停止 10 秒；超时要调查负载、导入和启动日志，不能直接放宽标准。清单/安装门禁通过不等于真实模型、渠道、VM、全套 PTY 或性能验收通过。

报告为输出目录中的 `distribution-report.json`，同时保留命令日志与制品摘要；只有 `status=passed` 才表示该完整门禁通过。Windows 的 Sandbox 安装受 Boxlite 平台发行限制，必须如实记录失败，并在支持的平台补齐；不能删掉 sandbox 目标后仍声称完整通过。真实环境条件见[测试说明](../开发/测试说明.md)。

GitHub Actions 配置包含 Ubuntu/Windows 检查；配置存在不代表已运行成功。手动 release workflow 生成构建产物，本地修改不自动提交、推送或发布。
